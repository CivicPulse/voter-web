# Quickstart: Live Election Results Visualization

**Feature**: `002-election-results` | **Branch**: `002-election-results`

## Prerequisites

- Node.js LTS (use `nvm use` to load from `.nvmrc`)
- voter-api running locally at `http://localhost:8000` (or configured via `VITE_API_BASE_URL`)
- `.env` file in project root (copy from `.env.example` if missing)

## Getting Started

```bash
# Switch to feature branch
git checkout 002-election-results

# Install dependencies
npm install

# Start dev server
npm run dev
```

## Architecture Notes

### Multi-Race Grouping

The backend stores one race per election record. The frontend groups elections by `election_date` to simulate multi-race election events. See [research.md](research.md) §1 for details.

```
/elections                          → GET /elections → group by date
/elections/2026-02-17               → GET /elections?date_from=2026-02-17&date_to=2026-02-17
/elections/2026-02-17/{electionId}  → GET /elections/{id}/results
```

### Auto-Refresh Pattern

```typescript
// In use-race-results.ts
refetchInterval: (query) => {
  const election = query.state.data?.election
  if (!election || election.status !== "active") return false
  return election.refresh_interval_seconds * 1000
}
```

### Map Layer Switching

The choropleth map supports three data layers, all using the same GeoJSON geometry with different coloring functions:

- **Leading Candidate**: Party color of the candidate with most votes
- **Precincts Reporting %**: Sequential color scale (light → dark)
- **Total Votes Cast**: Sequential color scale by percentile

### Test Infrastructure

```bash
# Run tests
npm test

# Run with coverage report
npm run test:coverage

# Run with visual UI
npm run test:ui
```

Test files go in `tests/` mirroring the `src/` structure. The custom render wrapper at `src/test/render.tsx` provides QueryClient and Router context for component tests.
